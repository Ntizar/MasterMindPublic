1 Tres capas de conocimiento

Mastermind no tiene una sola memoria. Tiene tres sistemas independientes que se complementan: memoria volátil (preferencias), skills (procedimientos), y repo GitHub (backup permanente).

🧠

Memoria Hermes

/hermes-home/memories/

Preferencias del usuario, entorno, lecciones aprendidas. Se inyecta en cada turno automáticamente. Límite: 2.200 chars de memoria + 1.375 de perfil de usuario. Compacta y enfocada en lo que importa a largo plazo.

📚

Skills Hermes

/hermes-home/skills/

240 procedimientos reutilizables en formato SKILL.md (YAML frontmatter + markdown). Cada skill es un directorio con instrucciones, scripts, referencias y plantillas. Se cargan con skill_view() cuando son relevantes para la tarea.

🔒

Repo GitHub

github.com/Ntizar/NtizarBrainMasterMind

Backup permanente de todo: skills, memories, config, scripts, notes. Commits frecuentes ("Backup semanal", "Stars Explorer"). GitHub Pages activo. Regla de oro: nunca se borra nada, solo se crea o modifica.

3 ChromaDB — el cerebro semántico

Una base de datos vectorial local que indexa los 240 skills. No busca por nombre, busca por significado. Es lo que permite que Mastermind encuentre el skill correcto sin saber que existe.

# Indexación: cada SKILL.md se convierte en un vector texto = name + description + tags + secciones del body embedding = modelo_embedding(texto) # vía API tu proveedor chromadb.collection.add(id, embedding, metadata, document) # Consulta: la petición del usuario se convierte en vector query_embedding = modelo_embedding("palabras clave") results = chromadb.collection.query(query_embedding, n_results=5) # → devuelve skills ordenados por similitud coseno
URL: localhost:8000 Colección: mastermind-skills Embeddings: modelo configurable Distancia: coseno Re-index: domingo 04:00 UTC
Auto-start: Si ChromaDB no responde, Mastermind ejecuta start-chromadb.sh y reintenta. Si sigue sin funcionar, fallback al sistema tradicional (cargar por dominio desde available_skills).

5 Skill Lifecycle — priorización automática

No todos los skills son iguales. Un script analiza el uso real (git log + notas) y re-clasifica cada skill en tres niveles según su actividad.

Fórmula de usage score: score = git_mentions × 0.4 + notes_mentions × 0.4 + partial_matches × 0.2
HIGH
MEDIUM
LOW
HIGH (≥0.6) — uso activo, siempre cargados MEDIUM (0.3-0.6) — uso moderado LOW (<0.3) — archivo, solo si se piden
Excepción: Los skills de mastermind/ (orquestación, ChromaDB, deploy) son siempre HIGH sin importar el score — son infraestructura crítica del sistema.

6 Scripts que mantienen vivo el sistema

Python y bash que automatizan indexación, aprendizaje, backup y análisis. Viven en /hermes-home/scripts/ y se ejecutan vía cron o manualmente.

consultar-skills.py

Búsqueda semántica en ChromaDB. Genera embedding de la consulta y devuelve skills por similitud.

indexar-skills.py

Indexa todos los SKILL.md en ChromaDB. Lee frontmatter, genera embeddings, guarda en lotes.

skill-lifecycle.py

Analiza uso real (git + notas, 30 días) y re-clasifica skills en HIGH/MEDIUM/LOW.

skill-learning.sh

Instala 1 skill nuevo del hub Hermes cada ejecución. Cola de ~120 skills priorizados.

backup-hermes-memory.sh

Copia memoria y SOUL.md al repo GitHub. Commit automático, push manual.

start-chromadb.sh

Auto-start de ChromaDB si no está corriendo. Usa venv Python aislado.

explorar-stars.py

Explora las stars de GitHub de David y genera skills nuevos a partir de repos interesantes.

ebbinghaus-decay.py

Repaso espaciado basado en la curva de olvido de Ebbinghaus. Refuerza skills poco usados.
